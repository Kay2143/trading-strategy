# 주식천재stock-research-agent 설계

## 목적

단순 종목 알림을 대체하고, 검증 가능한 근거와 리스크를 갖춘 의사결정 지원 에이전트를 운영합니다.

현재 단계의 목표는 매매 추천과 텔레그램 품질을 개선하는 것이며, 자동 매매는 포함하지 않습니다.

## 운영 원칙

1. 데이터와 소스는 실행 전에 검증합니다.
2. 모든 전략은 기준선과 비교합니다.
3. 모든 수치에는 표본 수와 조회 시점을 기록합니다.
4. 검증 실패 시 알림을 발송하지 않습니다.
5. 매매는 사람의 명시적 승인 없이는 실행하지 않습니다.
6. 자금 한도와 손실 한도를 넘는 요청은 거부합니다.
7. 운영 로그와 사후 검증을 분리 보관합니다.

## 파이프라인

```text
데이터 수집
  -> 데이터 무결성 검증
  -> 전략 후보 생성
  -> 시대별 백테스트
  -> 리스크 검토
  -> 품질 게이트
  -> 텔레그램 초안
  -> 사람이 승인한 경우에만 매매 후보로 승격
  -> 사후 추적
```

## 에이전트 책임

### Data Agent

- 조정종가와 거래량 데이터 수집
- 상장폐지, 거래정지, 액면분할 등 예외 처리
- 당일 미완성 봉 제외
- 데이터 출처와 조회 시점 기록

### Strategy Agent

- 기존 전략의 재현
- 명확한 진입/청산 규칙 생성
- 파라미터와 유니버스 기록
- 데이터 누수 방지

### Validation Agent

- 기준선 대비 성과 비교
- 시대별 및 롤링 윈도우 검증
- 거래 비용과 슬리피지 반영
- 과적합과 표본 부족 검사

### Risk Agent

- 최대낙폭과 손실 한도 평가
- 종목 집중도와 섹터 집중도 확인
- 반대 근거와 공시 위험 점검
- 품질 게이트 승인 또는 차단

### Reporting Agent

- 검증된 분석만 텔레그램 초안으로 변환
- 출처와 조회 시점 표기
- 단정형 매수 추천 금지
- 매매 가능 여부를 관찰/검토/승인 후보로 구분

## 데이터 저장

- 불변 원본은 `sources/`가 아닌 별도 데이터 저장소를 두어 원본을 보존합니다.
- 분석 산출물은 `backtests/`, `research/`, `reports/`에 보관합니다.
- 판단과 승인 이력은 `decisions/`에 기록합니다.
- 정기 분석은 후보와 5거래일 후 코스피 대비 결과를 `decisions/candidate_ledger.csv`에 축적합니다.
- 일별·주별 결과는 `reports/`에 보존하며, 누적 성과는 규칙 변경의 근거로만 검토합니다.
- 수동 매매 기능이 추가되면 브로커 응답과 체결 결과를 `logs/`에 기록합니다.

## 자동 학습의 범위

현재 단계의 "학습"은 모델 가중치를 자동 재훈련하는 뜻이 아닙니다. 검증된 자료 메모를 다음 분석에서 읽고, 고정된 후보 규칙의 결과를 사후 기록해 사람이 검토할 수 있게 합니다. 성과가 나쁘더라도 시스템이 스스로 기준을 바꾸지 않으며, 변경은 새 백테스트와 사용자 승인 후에만 수행합니다.

첫 자동 분석은 공개 일봉 가격 데이터만 사용합니다. 재무제표, 공시, 제품 트렌드가 연결되기 전까지는 실적 시즌·ROE/PER·차트와 매출의 괴리 분석을 완료했다고 표현하지 않습니다.

가격 기반 파이프라인은 KRX 시가총액 상위 종목의 일봉에서 엄격한 추세 조건과 유니버스 내 상대강도를 찾아 최대 3개까지 추가 조사 후보로 기록합니다. 강화된 RS 80 기준은 별도 백테스트가 끝나기 전까지 탐색 기준으로 표시합니다. 거래대금 하한, 데이터 수집률, 최신 종가 기준 검사를 통과하지 못하면 발송하지 않습니다. 후보가 없을 때는 보고서만 저장하고 텔레그램 알림을 생략합니다.

## 텔레그램 정책

초기 정책은 다음과 같습니다.

- 후보가 0개면 품질 게이트를 통과한 후보가 없다는 사실만 알립니다.
- 검증된 전략의 표본 수와 기준선 성과를 함께 제공합니다.
- 뉴스 요약은 별도 사실로 표기하고 투자 근거로 과도하게 사용하지 않습니다.
- 당일 미완성 데이터로 작성된 분석은 발송하지 않습니다.
- 동일 종목의 중복 발송을 차단합니다.

## 매매 구조

아직 매매 코드는 넣지 않습니다.

최종 매매 단계는 다음 순서로만 확장합니다.

1. 모의 매매
2. 소액 수동 승인
3. 규칙 기반 수동 승인
4. 일일 손실 한도가 적용된 제한적 자동매매
5. 확장 자동매매

각 단계는 이전 단계의 검증 보고서와 긴급 정지 절차가 없으면 다음 단계로 진행하지 않습니다.
